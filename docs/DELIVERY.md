# 流形开发计划与验收

目标是交付可以在登记设备上运行的独立粒子回答面板，并让两个不同提供方产生可继续操作的同类回答。本计划定义进入下一阶段的条件，不把架构文档、协议样例或旧 DOM 演示计为引擎完成。

## 阶段与退出条件

| 阶段 | 工作包 | 可交付结果 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| M0 显示可行性 | 建仓、环境锁定、WebGPU 画布、字形源、驻留格点、稀疏位移、诊断 | 不调用 AI 的固定中文、数字、细线、图片场景 | 唯一输出与粒子身份两项通过；小字可读；记录资源与性能 |
| M1 阅读与交互 | 文本映射、选择复制、滚动、键盘、无障碍桥、字体重编译 | 一份能准确阅读和复制的长文 | 缩放与重排后命中正确；减少运动和读屏可完成任务 |
| M2 场景与修改 | Schema、编译器、数据图、时间线、增量、事务、历史分支 | 固定图表和示意动画可局部修改与撤回 | 内容、图形、标签、命中同版本；异常事务不污染旧场景 |
| M3 媒体 | 素材登记、解复用、帧队列、媒体时钟、字幕和控件 | 一个有明确格式的本地短片 | seek 无旧帧回放；帧释放、暂停、静音和恢复通过 |
| M4 多 AI | 网关、两个不同提供方、能力协商、流式与取消、用量记录 | 可从自然语言生成并修改场景 | 相同契约通过；错误降级为粒子文字；没有偷偷重试收费任务 |
| M5 个人试用 | 同源启动、持久化、导入导出、设备矩阵、打包与文档 | 可复现启动的试用发行包 | 核心用例、恢复、数据保留与限制说明齐全 |

最先实现 M0 的可寻址粒子实验，不先做大量外壳或模型接入。M0 失败时调整密度、材质和表示，仍不允许用可见浏览器文字补洞。只有输出约束、阅读与性能取得共同可行点，才进入后续阶段。

## 固定场景矩阵

文字场景包括中文细笔画、数字、混合标点、12/14/16/24 CSS px、长段落、代码空格、组合字符、emoji、连字与双向文字。未通过的字种明确标记能力限制，不用某一字体的成功推广到所有文本。

数据场景包括正值、负值、零、null、不等间隔标签、长单位、重复类目和单点数据；表格、图形与复制使用同一数据源。图形场景覆盖半透明重叠、裁剪、旋转、旧位置清理和局部释放。

媒体先登记一个 720p/30fps 的短片样本，具体容器、编码、时长、音轨和字幕格式记录到 fixture manifest。1080p、其他编码和远程媒体分别扩展，不能由一个样本成功推导全部支持。

## 必过的粒子验收

关闭粒子阶段并使其缓存失效，回答区域全部内容应消失，包括字幕、提示、选择高亮和按钮。外壳和空板背景可保留。

调试接口选定一个正文边缘粒子、一个图表粒子和一个半透明层粒子，检查身份、改色、位移、恢复。原位置应恢复相应下层，新位置不得重复贡献；任意源纹理直接 blit 绕过粒子阶段判失败。

同一测试在静态、局部修改、减少运动、视频播放和质量降低下执行。WebGL2 等新后端必须独立通过，不以 API 兼容或截图相似替代验收。

## 交互与内容一致性

把每次操作的 presentedRevision、viewEpoch、目标和结果写入本地测试日志。滚动、字号改变、字体延迟加载及窗口缩放后选择同一句话，复制必须一致。图表标签变化和节点命中不得跨版本。

用户选字时到来冲突候选，验证延后或撤销；读屏正在阅读时不要无节制重新宣布全文。动画暂停时选择、焦点和语义顺序仍可用。IME 组合中的 Enter 不发送。

## 故障与事务验收

必须覆盖删除中间回答后撤回恢复原顺序、ready 后窗口变化而 commit 迟到、不同分支相同 revision 不串用缓存，以及重复事务、相同 ID 不同内容、乱序事件、事件缺口、过期基线、过期 viewEpoch、取消先于提交、提交先于取消和模型格式错误。每项检查已显示内容、持久化版本、资源释放和费用调用次数。

模拟编译前、ready 后、持久化后但呈现前崩溃。恢复只读取已提交快照；未提交候选不得冒充历史。设备丢失和前端刷新不能再次触发原请求或媒体生成。

多窗口测试一个写入者和一个只读窗口，写入租约过期后显式接管，旧写入者回执不能继续生效。

## 性能测试方法

性能数字是目标，尚非测试结果。第一档目标 60 fps，对应约 16.7 ms 帧间隔；受限动态档目标 30 fps，对应约 33.3 ms。同时记录 p50/p95/p99，不能只给平均值。

每条记录包含设备、系统、浏览器版本、后端、绘制像素、DPR、字体包、透明层、占用格点、活动运动粒子、视频规格与运行时版本。CPU 提交时间和可用时的 GPU 时间分别报告，不能用 requestAnimationFrame 间隔假充精确 GPU 耗时。

固定内容预热 30 秒、采样 120 秒，另做 20 分钟持续运行检查。目标是没有无法解释的持续资源增长、输入无明显排队、暂停后工作量回落。输入到下一可见反馈的拟定 p95 目标为 100 ms，模型网络等待另计。

资源预算记录应用可追踪分配及浏览器可提供指标，不宣称能精确读取所有设备显存。比较时同时给画质与密度；通过减少字号清晰度换来的帧率不得算同条件提升。

## 验证层次

本次 specs/validate.py 只检查协议规格与固定正反例，不检验 GPU、网络服务、无障碍或性能。之后单元测试负责纯逻辑，契约测试负责协议与状态机，浏览器集成负责真实交互，人工检查负责字形阅读和辅助技术，基准程序负责性能。

不为简单颜色调整编写重复实现的测试。必须给版本与资源生命周期这样的关键状态写对抗性用例。截图比较允许经标注的抗锯齿差异，但不能掩盖缺字、遮挡和坐标错位。

## 发布和可维护性

M5 交付启动说明、能力与限制、字体及依赖许可、数据目录说明、导出恢复流程、样例与诊断入口。API 密钥不得进入浏览器持久存储、场景包、错误日志或历史记录。

依赖锁与场景协议变更一起审查。主版本不兼容变更须提供迁移与回退策略；旧历史无法迁移时保留原始包并清楚说明。日志默认本地且不含内容，遥测另行由用户启用。

阶段通过后才估计下一阶段工程量。精确发布日期依赖 M0 的字体质量、透明图块成本及平台测量；当前不承诺固定周数。试用反馈优先修正读写任务失败，再扩模型和动效数量。
