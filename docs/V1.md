# 流形 · Forma 1.0 使用与交付说明

本版把独立面板、粒子编译器和本地模型网关做成一个无构建步骤的本地应用。浏览器原生 ES modules 加载 `app/`，Node.js 内置模块提供本地服务，不安装第三方 npm 运行依赖。

本说明记录实际运行范围。`PROJECT.md`、`DESIGN.md` 和设计阶段 Schema 保留较完整的目标，不能据此推断相应功能已实现。

## 运行条件

- Node.js 22 或以上。
- 支持 WebGL2 并能创建对应上下文的浏览器。禁用硬件加速或设备资源不足时可能无法启动画布；此时显示错误，不以普通文本层替代粒子回答。
- 本地示例、内置字体和短片不需要模型账号。在线模型需要用户自行配置可用的地址、模型和 API Key。
- 首版以桌面浏览器为主要环境。窄屏有导航折叠和输入布局，但完整跨浏览器、移动端和多设备矩阵尚未完成。

在项目根目录运行 `npm start` 或 `node server.mjs`，访问 `http://127.0.0.1:4173`。可用 `FORMAPORT=4174 npm start` 更换端口。在启动终端按 Ctrl+C 停止。

macOS 双击根目录 `启动流形.command` 会自动切换到项目目录、检查 Node、启动服务并打开浏览器。若端口上已有通过健康检查的 Forma 1.0 则复用；其他服务占用或健康状态无法确认时不会复用或结束对方进程。复用实例需在原启动终端停止。

## 一个组件完成编译与显示

```text
本地示例／用户 JSON／AI 回复
             ↓
    严格场景校验与内容解析
             ↓
       ParticleCompiler
    排版 → 颜色与覆盖率场
       → 粒子定位和交互
       → WebGL2 粒子绘制
             ↓
       最终粒子回答板
```

运行模块属于粒子编译器内部，没有独立通用引擎产品。内容源用未插入页面的 Canvas2D 画布计算文字、几何与媒体颜色；WebGL2 顶点程序按格点生成粒子，读取对应颜色和覆盖率，最终通过粒子绘制到唯一可见画布。源画布本身不会作为普通图片铺到回答板。

待机板中央显示一团不透明的黑色液体。移动阶段沿非线性曲线展开，同时从黑色逐步染成目标颜色；靠近目标时位置、颜色、覆盖率共同收稳。附着时已经形成内容，之后仍由可寻址的格点粒子显示。清晰模式中密集粒子接合以保留细笔画；颗粒模式改变采样间距和外观。选择高亮、悬浮信息、数据表和板内按钮也由粒子绘制。

2026-10-09 的整体架构修正采用统一目标计划与持久材料状态。初次展开时间尺度为 2600 ms，以固定 1/120 秒积分非线性目标弹簧及邻域速度耦合；材料沿途渐变颜料，接近目标后形成清晰内容。后续内容从当前材料状态重新分配，不凭空另画中央黑团。

密度与颜料场只由当前材料写入，再由粒子格点重建液面。内容格点始终查询材料绑定，包括已经完全附着时。驻留状态可简化为单材料查询，流动时邻域插值保持连续；运动中降低显示采样量，到位后恢复完整采样，均不绕过材料状态。当前不运行完整流体物理求解器。

指针位置和作用强度使用按实际时间求解的临界阻尼，运行模块按残余运动刷新到归零；支持长时间停留后离开、关闭扰动时平滑回落，减少运动时直接归位。

浏览器 DOM 负责面板外壳、输入框、设置与不可见语义信息。隐藏语义结构提供可访问性文本和控件，不能覆盖或替换粒子画面。复制读取保存的原文与数据，而不是对画面做 OCR。

材料池按画板初始有效像素面积分配 4096–12288 份带权材料，尺寸变化保留当前池身份。显示倍率最高取设备倍率 2，并有约 230 万画布像素预算；液面重建约 125 万格点上限。界面的粒子统计是提交格点总数，含透明格点与重建通道，不等于独立物理材料数量。源内容场与交互层的累计预算为 2400 万采样像素，并检查 GPU 纹理尺寸；这不是整个进程显存的硬上限。详细契约见 DESIGN.md。

## 已有体验

| 功能 | 本版实现 |
| --- | --- |
| 文字 | 中文与普通文本排版、长回答滚动、整段或拖选复制、选区引用追问 |
| 图表 | 柱状／折线、零基线、空值、数据点选择、切换图型、分页数据表与复制 |
| 动画 | 受限形状或自由分组的旋转、平移和透明度时间线；暂停、速度切换与重播 |
| 图片 | 读取本机图片，在颜色场中采样并由粒子显示 |
| 视频 | 浏览器视频元素在后台解码，粒子显示采样帧；播放、暂停与定位，当前默认静音 |
| 样式 | 清晰／颗粒、指针扰动、减少运动；系统减少运动偏好作为初始值 |
| 场景 | 导入／导出 JSON，模型纯文本转换为文字场景，结构化 JSON 严格校验 |
| 历史 | 浏览器本地最多 20 条最近场景快照，可以打开旧快照、清空列表 |
| 模型 | OpenAI 兼容 Chat Completions 与 Anthropic Messages 两类适配器 |

四个侧栏示例随应用提供。示例图表不是真实收入数据；轨道示意不具有真实天体尺度或物理精度；短片不是 AI 当场生成。未配置模型时，输入只通过关键词匹配示例或显示原问题，不会生成开放式回答。配置模型后，输入才会请求模型。

常用操作：Enter 发送，Shift+Enter 换行；Cmd/Ctrl+K 新面板；面板内拖动选择文字；选中后 Enter 引用追问；Cmd/Ctrl+C 复制选区或面板文字；Escape 清除选择；方向键或滚轮浏览长内容。

## 模型配置与请求边界

在「连接模型」填写接口类型、API 根地址和准确的模型 ID。OpenAI 兼容地址示例为 `https://api.openai.com/v1`，Anthropic 为 `https://api.anthropic.com/v1`；本地兼容服务可使用 `http://127.0.0.1:端口/v1`。填写完整的 `/chat/completions` 或 `/messages` 路径也可识别。

保存成功只表示配置格式通过校验，不能证明 Key、模型权限或服务可用。首次生成才请求提供方。两种适配器已通过本机假上游测试，**未使用真实 API Key 完成提供方在线联调**，不能将其表述为真实模型验收。

Key 仅保留在本机服务进程内存中。配置读取 API 不返回 Key，服务重启清除配置；修改连接需要重新填写 Key。已连接模型时，问题、当前面板文字和选中的引用会发送给配置的提供方。本地图片与视频的二进制内容不会上传，但媒体标题或说明可能出现在文本上下文中。

网关等待上限 60 秒，JSON 输入上限 64 KiB，上游响应上限 2 MiB，同时至多 4 个生成请求。前端场景另有较小的内容限制，所以收到的回复仍可能被场景校验拒绝。停止、断开连接和客户端断开会取消在途请求；更换配置也取消旧请求。错误只返回受控说明，不直接返回上游完整错误体或 Key。

服务检查 Host 和 Origin；静态文件只从 `app/` 读取，拒绝目录穿越及指向目录外的符号链接；CSP 不允许内联脚本或模型提供的远程脚本。模型输出只作为数据，不执行 JavaScript、HTML 或系统命令。

## 当前执行的协议子集

实际入口为 [`app/scene-validation.js`](../app/scene-validation.js)。版本仍为 `panel-scene/0.3`，但比设计阶段完整 Schema 更严格：

| 项目 | 1.0 接受范围 |
| --- | --- |
| 大小与树结构 | 至多 128 KiB、64 节点、树深度 8，累计文本 10000 字符 |
| 分组布局 | column 与 free；不支持 row。free 要求 viewBox，直接子项用 absolute |
| 文字 | title、body、caption、code 四种角色 |
| 图形 | circle、rect、line 和固定材质集合 |
| 图表数据 | 至多 16 个数据集，每集 200 行、32 字段；图型为 bar、line |
| 媒体引用 | 本地登记的 assetId；不从模型给出的 URL 下载媒体 |
| 动画 | 至多 32 条；仅 free 区域内绝对定位的形状或自由分组；旋转、X/Y 平移、透明度 |
| 动作 | 校验 ask-selection、set-chart-type、toggle-playback，至多 64 个；当前界面提供固定的引用、图表和播放控件，不按任意 action label 生成自定义工具栏 |
| 来源与字幕 | sourceRefs 只能为空；独立 posterAssetId、captionsAssetId 尚不支持 |

未知字段和无效引用、时间线或内容会报错，当前画面保留。普通文本可转换为文字场景。看起来像结构化 JSON 但格式错误的回复会明确失败，不静默编造成图表或改变含义。

`specs/` 下的参考 Schema 与检查器用于设计契约，不是当前客户端的全部可执行能力。网关提示词优先要求较小的文字／图表／形状子集，避免模型自行声明媒体或权限。

## 保存与媒体生命周期

最近面板以 `forma.history.v1` 保存在当前浏览器、当前站点的 localStorage，保留最近 20 条场景快照。显示偏好另存于 `forma.preferences.v1`。更换端口、浏览器或用户目录会使用不同的站点存储；清理浏览器数据会删除这些记录。

这不是 SQLite、完整对话分支或耐久事务日志。旧面板继续输入会新增快照，没有完整父子分支图。生成请求携带当前显示内容，未实现完整历史消息自动回放。

本地文件通过临时 Blob URL 在当前页面会话中读取，不复制进项目目录，不保存到 localStorage，也不随场景 JSON 导出。单文件上限 150 MiB；实际可播放格式由浏览器解码能力决定，扩展名本身不保证兼容。媒体缓存会清理不再使用的旧文件，不能作为资产仓库。

刷新、关闭页面或清理媒体缓存后，历史中可能只剩媒体引用，界面会提示重新导入。内置 sampleVideo 可以重新加载随应用附带的短片。JSON 导入不自动下载远程媒体，导出不包含视频、图片或字体二进制内容。

## 验证记录

服务侧已运行 `node --test tests/server.test.mjs`，13 组测试通过，覆盖两种接口负载、配置生命周期、同源保护、输入上限、文件隔离、Range、重定向拒绝、错误脱敏、响应上限、取消、断线与超时。全部模型请求在测试中指向本机假提供方，未使用真实模型服务或收费 API。

项目整体检查入口：

```sh
npm test
npm run check
```

2026-10-09，统一材料架构重构后，在本机 Codex 内置 Chromium 155 / WebGL2 / DPR 2 验证：`npm test` **45/45**，`npm run check` 通过，真实 GPU 验收 **16/16**。完整结果见 [material-pipeline-qa.json](../artifacts/material-pipeline-qa.json)。此前的 `liquid-cohesion-*` 文件只代表旧实现，不作为当前架构的验收依据。

这次验收以整体显示机制为对象：

- 同一材料池中等待、流动与附着数量守恒，全部材料到位后不残留额外中央黑团；99% 与 100% 画面逐像素一致。
- 故障注入将全部材料移出视口，实际 GPU 输出完全透明；恢复同一份状态后液面恢复。这直接检测独立黑团与附加液桥。
- 100% 驻留后只修改上传的材料位置，144 个显示像素随之整体移动 20 px；源图与布局未改，证明没有终点绕过材料的显示分支。
- 内容帧更新可在原来透明的区域成像；目标运动、滚动与视口变化保留材料池与归属纹理。
- 保留原有单格点修改、前后层与半透明合成、扰动稳定性、统一关闭显示、非法场景事务和资源释放检查。
- 1158 字符中文长文在 320 / 800 px 下重排为 73 / 25 行，字符和末尾显示完整。
- 本地 640×360 短片从 0.15 s 定位到 4.20 s，图像区 361960 像素变化，页面没有 video 叠层。
- 单元测试还覆盖新回答继承位置、速度与颜料，30 / 60 / 120 Hz 固定步一致性，以及目标计划的稀疏覆盖、动态换色与相机变换。

主面板和 `/qa/liquid.html` 直接使用同一编译器及渲染模块。`/?qa=1` 将历史和偏好放在内存中，避免验收改写用户记录。海岸图实测录屏见 [material-flow-space-pi.mp4](../artifacts/material-flow-space-pi.mp4)。图片还原检查针对编译器缩放后的颜色场，不代表原图在任意窗口下无缩放损失。

本次通过的断言证明材料状态与显示管线在受测环境下符合约束；它们不等于完整流体物理、跨设备帧率承诺或最终视觉质量结论。Safari / Firefox、真实移动设备和 GPU 显存矩阵仍未完成。

## 当前未实现

没有独立 WebGPU 或 Canvas2D 显示后端，没有复杂脚本场景、任意 HTML、3D 引擎、模型工具执行、视频／图片生成、字幕文件导入、跨设备同步、多人编辑、插件市场或直接接管第三方聊天应用。

文字排版使用浏览器字形能力及当前换行、选择逻辑，没有实现设计稿中的完整 HarfBuzz/WASM 管线。运行时采用 WebGL2 格点粒子与逐对象颜色场，没有完整物理液体模拟、任意海量层级场景优化或设计稿中全部事务与增量提交能力。

后续优先根据 1.0 使用反馈改善清晰度、交互与设备性能，再扩充协议、持久化和模型兼容性。
